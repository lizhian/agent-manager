# Native Skills service

`SyncSource(ctx, "owner/repo", onProgress)` installs or updates through the existing `npx --yes skills add owner/repo -y` then `npx --yes skills list --json` workflow. `Options.Runner` is the external-command seam; the default uses the shared bounded desktop PATH resolver, captures exit status/stderr, and imposes a five-minute command deadline. Node/npx remains a real external dependency for normal installation. Existing catalog browsing does not require it.

The source writer lock prevents conflicting activation/sync operations. Download/preparation leave catalog reads available; committing uses the service lock briefly. Names, returned paths, copied symlink targets and cycles are checked before publishing the staged mirror. SQL upserts retain IDs and surviving activation flags. Owned links, old mirror and transaction are compensated on publish/commit failure. Unknown/manual paths are preserved and reported as conflicts. Tests use temporary homes and command/filesystem substitutes.

For local UI validation without downloading any source, build `go build -o /tmp/agent-manager-skills-fixture/bin/npx ./cmd/skills-fixture`. Give the app a temporary `--data-dir` and a **test-only login shell** whose PATH puts this fixture bin first; production login PATH normally precedes inherited PATH. Set `AGENT_MANAGER_SKILLS_FIXTURE_MODE` to a temporary mode file. Contents `1` return keep/gone; `2` return keep/new; `fail` simulates nonzero command+stderr. Each fake add sleeps two seconds so progress and browsing can be observed. This is a controlled subprocess test, not evidence that an actual upstream npx download ran.

`UpdateAll` keeps the source writer lock for the batch and reports each source independently; successful sources remain committed when another fails. Its result includes final catalog snapshot, source success/failure counts, installed/removed counts and source-specific errors. `RemoveImpact` rereads installed/enabled counts; `RemoveSource` checks all derived paths for exact ownership before moving the old mirror aside and removing catalog/links under compensation. Unrelated files and foreign links are untouched; manual collisions are actionable errors.

The UI fixture also supports mode `mixed`: source `example/failure` fails while other sources update to the second dataset. Install both sources with mode `1` first, then change the same mode file to `mixed` for a mixed-result batch demonstration.
